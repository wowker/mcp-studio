Tool 测试单元规范定义 (Definition & Analysis Sheet)

目标关联服务: inventory-service / production-mcp-01
测试目标 (Goal)
验证商品在预发布阶段的批量创建与结构校验能力。确保包含多变体（SKU）、动态属性组（Specifications）及预定库存配额时，能够成功写入预发布临时隔离库，并正确生成不可逆的唯一跟踪批次号（batch_tracking_id）。
分析边界 (Analysis)

核心逻辑：该 Tool 作为异步批处理代理，在入参验证通过后直接向内部 Kafka 事件总线广播 product.pre_publish.draft 事件。响应体包含轻量级 ACK 与处理状态，不直接返回最终落库完整实体。

幂等性契约：当传入相同的 client_request_token 时，Tool 必须返回上一次创建批次的引用句柄，杜绝重复写入脏数据。

排除范围 (Exclusions)
  • 不执行真实结算或付款：该单元仅覆盖商品结构入库，不触发财务中台扣费与结算钩子。
  • 不发起外部 CDN 图片物理转码：图片资源仅校验 HTTPS 协议合规与 URI 可达性格式，不验证文件哈希内容。
  • 跨服务下游通知：针对 ERP 与搜索索引同步的延迟通知，列为下游自动化测试套件职责，本单元直接 Mock 处理。
前置准备 (Preparation)
#1 确保测试商户租户凭据 (Tenant Fixture) 已预置
ENV_STAGING_KEY 必须具备 `catalog:product:create` 与 `warehouse:pre_allocate` 只读/只写细粒度权限。
#2 预留测试分类 ID: 10482 (Electronics/Peripherals) 已就绪
关联规则已在当前活跃沙箱环境中预先同步，以确保参数外键约束校验正常通过。
清理策略 (Cleanup)
测试执行轮次结束后，外部 Agent 应在收到判定信号后，调用下游专用反向补偿接口 catalog.purge_test_batch 传入 batch_tracking_id 清理临时数据。沙箱环境设有 24 小时兜底 TTL 自动回收机制。
