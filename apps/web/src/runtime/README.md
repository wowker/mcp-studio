# M2 browser runtime

Production code in this directory does not import the M0 oracle. `configuration.test.ts` runs the 28 shared v1.1 configuration cases, and `environment.test.ts` runs all 14 shared environment cases. The SDK is locked to TypeScript MCP SDK 1.29.0 in the root package lock.

`buildLayers` filters project, connection and environment identities before merging in project base → project environment → connection base → connection environment order. `resolveEnvironment` exposes only safe rows to rendering; use `read` / `readDefinition` solely for ephemeral connection material. Definition-ID authentication accepts only the effective winning definition. Limits: 256 definitions, 4096 traversal steps per resolution, 64 nested levels. Missing high-level personal values never fall back.

`MemoryVault` stores credentials by user/project/connection, personal values by user/project/definition. It does not persist. `clear`, `removeCredential` and `revokeProject` advance an invalidation generation, which fences late OAuth replies. Scoped invalidation events disconnect matching user/project/connection sessions on credential expiry, removal or replacement, even without a mounted service panel. The UI additionally disconnects all browser sessions and cancels OAuth on identity expiration, logout and revoked access. Queued render-observed expiry is fenced against credential replacement.

`BrowserSession.connect` receives an authorization callback which must call the platform's current session-access endpoint. Returned user/project/connection/config version/environment must match before any target traffic. Explicit HTTP/SSE uses the real SDK; no platform MCP proxy, automatic transport/channel switching, Tool catalog, Tabs or execution exists here. Target fetches omit cookies and reject redirects. Only the chosen target origin receives configured headers; same-origin SSE message endpoints are supported. UI snapshots contain sanitized server name/version and capability names, never tokens, raw SDK errors or protocol bodies.

Browser failures intentionally use `network_or_browser_policy`: browser APIs do not reliably distinguish CORS, local-network policy, DNS and connectivity. HTTPS → non-loopback HTTP is prechecked as mixed content. Trustworthy loopback HTTP reaches actual browser enforcement; this does not imply permission from public HTTPS origins on every browser. Remaining compatibility is T02's deployment/browser matrix. Mixed-content behavior follows [W3C Mixed Content](https://www.w3.org/TR/mixed-content/).

## OAuth support profile

Based on the official [MCP 2025-11-25 Authorization specification](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization): resource metadata discovery through WWW-Authenticate (when present), then path/root well-known fallback; OAuth metadata and both OIDC well-known forms; resource in authorization and code exchange; S256 PKCE; state, issuer, exact callback origin/source and one-shot consumption. Scopes come from the challenge, configured request, or protected resource metadata. Access tokens use target Authorization headers only. Callback helper removes all query parameters immediately, before messaging the exact same-origin opener.

This first implementation supports **pre-registered public clients**. No client secrets, dynamic registration or hosted client metadata document. Authentication metadata, authorization and token endpoints require HTTPS. Redirects are refused during discovery and token exchange. Declared resource must exactly match the selected MCP resource. The AS authorization/token endpoints must share the declared issuer's origin (`oauth_restricted_endpoint` otherwise); providers must include `iss` in the callback. Metadata/token endpoint query parameters are unsupported. The authorization popup endpoint must use a different hostname from the platform (`oauth_platform_origin_conflict` otherwise), even when ports differ: top-level browser navigation cannot use fetch's `credentials: omit`, and cookies are host-scoped rather than port-scoped. Resource/token/discovery fetches still omit cookies. These are deliberate narrow profile restrictions, not claims of universal OAuth support. Restricted providers require a separately configured, saved and manually connected Agent in M5; M2 reports Agent unavailable and does not switch channels.

Refresh tokens returned by the AS are discarded. OAuth access tokens retain original resource metadata, and BrowserSession refuses another resource after the connection URL changes. Expired credentials require explicit reauthorization; there is no cross-resource refresh pathway. Pending verifier/state and access tokens stay only in browser memory. Authorization success means authorized awaiting manual connection. User cancellation, popup closing, expiry, invalid callbacks, token failure and permission invalidation do not report successful authorization.

`OAuthOptions.allowLoopbackHTTP` is an explicit **development fixture-only** exception for local mock AS endpoints. Production UI leaves it disabled. Real browser integration fixtures use temporary self-signed HTTPS certificates and an explicit browser test certificate exception instead.
