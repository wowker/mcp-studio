## 二、核心问题：e2e 覆盖缺口（重点）

### 2.1 事实：修复前 4 处 axe 断言，扫的是同一个页面同一个状态

修复前的全部 axe 检查（2 个 spec × 亮/暗两主题）：

| Spec | 位置 | 扫描时机 | 扫描对象 |
| --- | --- | --- | --- |
| `i18n-smoke.spec.ts` | 第 58 行（浅色） | Run 完成、结果区渲染后 | Tools 调试工作台 |
| `i18n-smoke.spec.ts` | 第 72 行（深色） | 切深色主题后 | Tools 调试工作台 |
| `core-debugger.spec.ts` | 第 402 行（浅色） | 点开「请求与结果」Tab 后 | Tools 调试工作台 |
| `core-debugger.spec.ts` | 第 409 行（深色） | 切深色主题后 | Tools 调试工作台 |

四道断言看起来分散在两个 spec、覆盖双语双主题，**实际全部落在同一页、同一状态**：Tools 调试工作台、单次 Run 已完成。

### 2.2 覆盖面矩阵（修复前）

| 页面 / 状态 | axe 覆盖 | 结果 |
| --- | --- | --- |
| Tools 调试工作台（Run 后） | ✅ zh/en × 亮/暗 | 绿 |
| **Servers 空态**（`server-tabs__empty`） | ❌ | 2.91 违规未被发现 |
| **Servers 表格**（表头「连接名称」「操作」） | ❌ | 4.38 违规未被发现 |
| **连接弹窗**（认证分组 / Bearer） | ❌ | 未检查 |
| 运行历史 | ❌ | 未检查 |
| 环境变量 | ❌ | 未检查 |
| 脚本页 | ❌ | 未检查 |

违规点与未覆盖页面**完全重合**——不是巧合，而是覆盖矩阵决定了漏检位置。

### 2.3 三层成因

**成因一：同页同状态的重复覆盖造成"覆盖充分"的错觉。**
两个 spec 各自跑亮/暗两次，看起来是 4 道关卡，实际是同一状态重复 4 次。新增页面（Servers 是主入口）从未进入扫描范围。

**成因二：视觉快照只比像素，不做对比度判定。**
4 张 baseline 全部是 `tool-debug-*`，与 axe 的覆盖范围完全一致。快照能抓到像素漂移，但对"文字变浅到不合规"这类变化只能记录、不能判定——本次 `--ui-text-subtle` 的改动恰好就属于这一类。

**成因三：一次 token 修复造成了"对比度已达标"的错误结论。**
`1ce9668` 修 64 处 color-contrast 违规时，违规**全部指向 `--ui-text-muted`**；把该 token 从 `#737d78` 调到 `#6a746f` 后 axe 立刻转绿。
这个绿灯掩盖了两件事：
- `--ui-text-subtle` 从未被任何断言触达，其浅色合规性无人校验；
- axe 只证明"被扫到的那个页面达标"，不等于主题级达标。

### 2.4 后果与发现路径

浅色 `--ui-text-subtle` 在所有浅色表面上只有 2.63–2.91，属于明确的 WCAG AA 失败，但：

```
typecheck ✅ → unit 796 ✅ → build ✅ → e2e 6/6 ✅
```

全部门禁绿灯。最终由**人工浏览器逐页扫描**（切浅色后按页面枚举文本节点、逐个算对比度）才发现。

这说明当时门禁的设计缺口不在"跑不跑"，而在"扫哪里"。

### 2.5 修复方式：嵌入式断言，零额外成本

在 `core-debugger.spec.ts` 既有引导流程中插入 3 处 axe 断言，不新增 fixture、不新增用例：

| 断言点 | 触发时机 | 覆盖的关键元素 |
| --- | --- | --- |
| ① Servers 空态 | 创建项目进入 Servers 后 | `server-tabs__empty`、空表格、页面副标题 |
| ② 连接弹窗 Bearer | 打开弹窗并切到 bearer | 认证分组标题、Bearer Token 输入框、字段说明 |
| ③ Servers 表格 | 保存连接后出现数据行 | 表头「连接名称」「操作」、状态徽章 |

选择这三个点的理由：
- 它们恰好是本轮全部违规所在，同时又处在流程必经路径上，无需额外导航；
- Bearer 状态是弹窗 UI 超集（含基础字段 / 认证 / Headers / 传输方式四组），一次扫描覆盖全部分组；
- 表格数据行覆盖了"表头 `--ui-table-head` 底色 + 次级文字"这一最容易失守的组合。

### 2.6 覆盖现状（修复后仍有空白）

| 状态 | 现状 |
| --- | --- |
| Servers 空态 / 表格 / 弹窗 | ✅ 已纳入 |
| Tools 调试工作台 亮/暗 双语 | ✅ 已有 |
| 运行历史 | ❌ 仍无 axe 断言 |
| 环境变量 | ❌ 仍无 axe 断言 |
| 脚本页 / JSON 全屏 | ❌ 仍无 axe 断言 |
| OAuth 授权流程 | ❌ 无环境 |

结论：缺口从"主入口完全空白"缩小到"次级页面空白"，尚未覆盖完整。补齐方式可直接复用本轮模式（在同一 spec 的既有流程里插断言）。

## 四、视觉体系变化

### 主色（紫 → 青绿）

| Token | 亮色 | 暗色 |
| --- | --- | --- |
| `--ui-accent` | `#267565` | `#85cfb5` |
| `--ui-accent-strong` | `#1c5a4d` | `#9adcc5` |
| `--ui-accent-muted` | `#e8f2ee` | `#2f4a3b` |
| `--ui-accent-border` | `#cfe3da` | — |

暗色 `accent-muted` 由 `#293f34` 调亮到 `#2f4a3b`：原值与 `surface-muted` 仅差 6 个十六进制步进，侧栏当前项与默认项肉眼无差别。

### 文字层级（浅色）

| Token | 调整前 | 调整后 | 语义 |
| --- | --- | --- | --- |
| `--ui-text-muted` | `#6a746f` | `#65706a` | 次级信息文本，AA 必须 ≥4.5 |
| `--ui-text-subtle` | `#8f9a94` | `#66706b` | 仅装饰/豁免层（禁用态、占位符、图标、边框） |

token 定义处新增契约注释；并把 3 处错配的承载信息文本（空态提示、运行 ID、表单约束提示）归位到 muted——值取等、零视觉变化，但避免了"subtle 承载信息"这一结构性隐患再次发生。

### 布局与响应式

- Tool 目录 300 → 236（拖拽区间 204–320），行高 40 → 32
- Servers 表格行高 11px / 0.8rem 字号，操作列 `width: 1%` + `nowrap`
- 连接弹窗 header + 可滚动表单网格，底部操作条 sticky
- 弹窗四组视觉块：基础字段 / 认证 / Headers / 固定传输方式
- ≤1000px：表格横向滚动、侧栏 192→156px、目录 180–220px
- ≤640px：弹窗全宽、表单单列、侧栏收起

## 七、限制与未覆盖

- 浏览器核对使用临时数据目录（`/tmp/mcp-ui-data`）与本地 fixture Server，**未覆盖真实远程 MCP 与 OAuth 回调路径**。
- 响应式只有断点样式，**无真机/多设备验证**。
- 运行历史、环境变量、脚本页仍无 axe 断言（见 2.6）。
- 已保存请求、Tool 定义、脚本、Tab 右键菜单、JSON 全屏完整流程未逐页打样。
- e2e 新增断言的负向验证（回退 token 观察断言失败）被安全策略拦截未执行；该结论由浏览器实测的旧值 2.91 / 4.38 间接支撑。
- 截图取证在部分时段不可用（标签页节流），改用计算样式取值。

## 八、下一步建议

1. **优先补齐 axe 覆盖空白**：运行历史、环境变量、脚本页按本轮模式在既有 spec 中插断言，成本低、收益直接。
2. **把"主题级达标"变成门禁而非人工结论**：可考虑对设计 token 增加静态断言（读取 token 值计算对比度），让"某个 token 不合规"在 CI 阶段暴露，而不是依赖某个页面恰好被扫到。
3. 移动端真机/多设备验证，补齐 ≤640px 的交互细节。
4. 真实远程 MCP + OAuth 路径的视觉与 a11y 复核。
5. 已裁剪功能残留清理：`START-DEVELOPMENT.md` 旧路径、A01–A60 验收清单按新工程重建（M8）。
