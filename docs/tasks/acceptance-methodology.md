# A01–A60 两版验收方法论

日期：2026-10-29。状态：**已确认**（2026-10-29 用户确认 D-A～D-D 全部按建议落地）。

本文把 E01 已落地的「适用形态」标注（45 两版 / 15 仅云版）成文化为可执行的验收规则，回答三个问题：哪些条目在哪个形态有证据义务、证据强度要求是什么、什么算正式签收。不改变 A01–A60 的正式预期结果文本；[06 验收清单](../design-baseline-v2/design-handoff/06-handoff-and-acceptance.md)仍是唯一预期来源。

## 1. 验收基线与历史证据处置

- **验收基线 = 当前 main（fff4f9b，含 E00–E10 发行形态拆分）**，不是 M7 冻结源 3056a6b。E 系列改动了认证入口（E04）、配置层（E03）、平台启动（E05/E08）、打包（E06/E10），旧证据基线 b3b6fa3 不能代表当前代码。
- **新基线门禁**：`tests/evidence/acceptance-baseline/`，完整 verify（合同、Node 固件测试、前端类型/测试/构建、真实 PG 全量 Go、vet、两版构建、单机版冒烟、四目标 Agent、运维/部署、浏览器旅程），云版与单机版分别出结论。
- **工具链约束（2026-10-29 登记）**：门禁在 **Node 24.x** 下运行，与历史冻结 manifest 记录一致（v24.21.0）。实测 Node v26.11.1 下 vitest 3.2.7 的 jsdom 环境装配会跳过 `localStorage`（Node 25+ 暴露原生 `localStorage` 全局但无 `--localstorage-file` 时为 undefined，vitest `getWindowKeys` 过滤逻辑命中 `k in global` 即跳过复制），前端 416/421 测试失败。失败证据保留在 `verify-node26-failed.log`。Node 26 适配（升级 vitest 或钉死 engines 上限）不在本次验收范围，另行决策。
- **历史 V01 证据（b3b6fa3 及四轮补证）处置**：E 系列触及的领域（认证入口、配置、启动、打包、发行标识）一律重验，不引用旧证据；未触及的领域（页面矩阵、脱敏、队列语义、记录/保存语义等）可作辅助引用，但**不单独构成签收**——签收以当前代码上重跑的证据为准。

## 2. 适用形态判定规则

E01 已逐条标注并登记（CSV 第 12 列、`m7-acceptance-index.json` 的 `editions`/`editionsNote`、v01-assertion-audit.md 判定节）。本节把判定逻辑固化，供执行与争议时援引：

- **R1（仅云版判定）**：场景主体依赖第二个真实用户、角色差异、邀请生命周期或会话生命周期 → 仅云版。单机版无证据义务，也不会因跳过角色校验而记假失败（012 Q7/Q8）。
- **R2（标注不改原则）**：执行两版项时若发现某子条款实质依赖角色/成员语义，不擅自改标注、不拆分条目；登记争议并退回确认。
- **R3（单机版授权底线）**：单机版跳过角色与成员资格校验，但**保留按项目归属过滤**（012 Q8）。两版项在单机版取证据时，凡涉及多项目数据的场景必须显式断言项目过滤仍生效——这是单机版授权语义下唯一的隔离边界。
- **R4（单机版证据来源）**：单机版证据必须来自 `apps/local` 构建形态（`-tags local`，内嵌 PG 或开发态编排），回环 HTTP；用云版进程模拟单机行为不算数。

## 3. 证据强度

- **云版**：沿用 V01 标准——真实 PG、真实邮件夹具、真实浏览器旅程、API 级断言；测试 helper 不替代生产认证/权限/SDK/队列。
- **单机版**：真实 `apps/local` 进程（临时数据目录或打包布局），浏览器旅程走回环；断言标准与云版同源（同一份业务代码），但证据需体现单机形态特征（免登录本地主体、回环无 TLS、内嵌 PG）。
- **两版项的证据义务（待确认 D-B）**：建议**两版各自独立完整证据**——行为约定承诺同一份业务代码两侧同效，签收即是对该承诺的逐项验证；浏览器旅程在单机版跑同一套（回环），不裁剪。
- **环境受限项保持待验**：实机/介质/人工类（T02 调用路径矩阵、T32b 人工、签名与公证、三 OS 系统凭据库、内嵌 PG 三 OS 首启）缺环境时不降级、不豁免，CSV 与审阅中显式保留待验。A41/A42 为两版且单机侧同样依赖系统凭据库与真实 OS 确认（editions-spec 新增待验项）。

## 4. 正式签收标准

单条 A 项签收需同时满足：

1. **实现版本**：明确的 commit（验收基线或其后的修复提交）。
2. **形态证据齐备**：仅云版项 = 云版证据；两版项 = 云版 + 单机版各自证据（依 D-B 结论）。
3. **门禁绿**：对应形态相关门禁在证据版本上退出码 0。
4. **只读审阅**：独立审阅无 Critical/Important；Minor 登记。
5. **逐条登记**：CSV 状态由「待验收」改「已签收」，逐条进行，不批量勾选（AGENTS.md）。

环境受限子项不阻断条目其余部分的验收推进，但**条目不签收**直到其子项全部解除或经明确授权豁免。
