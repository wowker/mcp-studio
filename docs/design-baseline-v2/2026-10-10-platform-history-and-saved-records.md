# 平台调用历史与已保存请求、响应

日期：2026-10-10。状态：设计与可交互预览已更新；尚未实现 Go 平台持久化或真实 MCP 调用。补充[本地优先执行架构](./2026-10-10-local-first-mcp-architecture.md)。

## 需求与产品边界

根据用户补充，平台除用户、团队、项目和配置外，也负责记录调用历史、请求参数、响应及用户主动保存的记录。历史上传是正常调试流程的一部分，不再默认“仅本地、按需上传”。MCP 认证信息仍默认留在本机；平台保存业务参数与响应不等于保存 OAuth Token、API Key 或其他 Secret。

业务导航保持 Server 配置、Tools 调试、环境变量和调用历史四个入口。“调用历史”页面提供“调用历史 / 已保存”两个分类；Tools 内提供“调试 / 工具定义 / 调用历史 / 已保存”。工具内两个集合精确按 projectId + connectionId + toolName 筛选，不跳转到总历史。

stdio 也使用同一套 UI。普通网页通过本机 Go Agent 启动 stdio MCP 子进程、读写标准输入输出，前端继续负责发起操作和显示结果。浏览器 Web Worker / Service Worker 不提供启动任意本机进程的能力。此预览没有加入真实 Agent 或 stdio 配置执行。

## 两类记录

| 类型 | 产生方式 | 内容 | 用途 |
| --- | --- | --- | --- |
| 调用历史 Run | 每次调用自动记录，包括失败、取消及结果未知 | 执行时的参数快照、返回响应或缺失原因、Tool 定义、执行人、连接、环境、状态、耗时和来源 | 追溯与排障 |
| 已保存记录 SavedRecord | 用户明确保存并命名 | 请求快照；或一次调用的请求 + 响应快照；名称、备注、可见范围与来源 | 参数复用和保留有价值的结果 |

保存请求只冻结当前参数，不附上当前结果区中较早调用的响应。保存记录使用同一次 Run 的参数和响应，不能把已修改但未执行的草稿与旧响应拼接。响应为失败结果也可以保存；没有响应时保留明确的缺失状态，不生成假成功内容。

SavedRecord 保存独立快照，不只保存 runId 指针。清理未固定历史不能删除用户已保存的参数与响应。编辑名称、备注和可见范围不改写执行快照；需要更改参数时载入新调试草稿，执行或再次保存。

## 页面流程

1. 参数区域的“保存请求”打开页内保存页面，展示名称、备注、可见范围及冻结后的参数预览。
2. 结果区域的“保存记录”，或历史详情页的同名操作，打开同一保存页面，展示对应 Run 的请求与响应。
3. 默认范围为“仅本人”。Maintainer 可选择“项目成员”；Developer 可保存私人记录；Viewer 仅查看获授权记录。
4. 保存成功进入已保存记录详情，显示原连接、内容类型、保存人和来源。原始快照只读。
5. “载入参数”创建独立的新 Tool Tab，保留来源 project / connection / tool 与记录 ID；不自动调用，不把保存的响应当成新 Tab 的执行结果。
6. 分类列表支持名称 / Tool / 备注搜索及可见范围筛选。工具内筛选与总集合筛选分别保存，切换工具或项目不串状态。
7. 保存取消返回来源页面；切换语言、主题和侧栏保留保存表单与业务草稿。浏览器前进 / 后退支持集合和详情路由。

历史显示平台记录状态：已记录、等待上传、上传失败。上传失败的重试仅同步原 runId 的参数、结果和事件，不再次执行 MCP Tool。预览提供失败与待上传示例及重试演示，所有数据仍只在内存中，刷新恢复初始示例。

## 正式版状态与数据契约

调用链与记录链分开：浏览器 / Agent → MCP Server 负责执行；浏览器 / Agent → Go 平台负责记录。

在线正常流程先由平台校验项目权限并接受脱敏请求快照，返回 runId 与配置版本，再由选定本地执行组件发起调用。调用完成后幂等补交响应与终态。平台不可用时默认阻止创建新的在线项目调用，避免静默丢失历史；如后续提供离线调试，必须显式标记并由 Agent 本地队列补传。

执行状态与记录状态分别管理。MCP 调用成功但响应上传失败时，仍显示成功的本地执行结果与上传失败状态。浏览器页面关闭导致结果无法补交时，平台记录响应缺失 / 结果未知，不能把“没有收到上报”判断为下游失败。Agent 可将待上传记录持久化，浏览器不能将含业务敏感内容的记录塞进偏好存储。

建议正式实体与字段：

- `Run`：teamId、projectId、connectionId、actorId、executor / deviceId、tabId、toolName、toolSnapshotId、参数与响应快照、configRevision、environmentRevision、credentialReference / revision、执行状态、记录状态、时间与耗时。
- `SavedRecord`：相同的项目 / 连接 / Tool 上下文、ownerId、visibility、名称、备注、独立请求快照、可选响应快照、响应状态、sourceRunId、创建与更新版本。
- `RunEvent`：runId、事件 ID、顺序和来源时间；平台记录接收时间。按 runId + 事件 ID 幂等写入。

使用 OpenAPI 和生成的 TS 契约，前后端各自执行运行时验证。API 草案在既有项目作用域下分组：

- `POST /runs`：授权并记录请求快照，服务端从登录会话确定 actor。
- `POST /runs/{runId}/events`：本人或受信任执行组件上报结果；拒绝跨项目、连接与执行者的数据。
- `GET /runs`、`GET /runs/{runId}`：分页读取获授权历史；工具筛选必须同时绑定 connection 与 Tool。
- `POST /saved-records`、`GET /saved-records`、`GET /saved-records/{id}`：保存和读取独立脱敏快照。
- `PATCH /saved-records/{id}`：以 revision 防止覆盖冲突；只更新名称、备注和可见范围。

凭据明文不进入这些 API；请求 / 响应上传前和平台落库时执行脱敏策略、体积限制与授权检查。客户端提交的 userId 不作为权限依据。“仅本人”是服务端查询与对象访问约束，不能只依靠前端隐藏行。载入已脱敏参数时，缺失的 Secret / 必填字段必须重新补齐或从当前有效引用解析。

本地报告的记录保留执行来源，不声称是平台独立观察到的下游审计证据。平台项目权限控制平台内的调用流程和数据访问，不能撤销成员已经拥有的下游秘密或阻止绕过工作台的独立请求。

## 可复用组件与验证

- `SavedRecordTable`：接收已授权且已限定作用域的列表，输出选择事件。
- `RecordSnapshots`：展示只读参数与可选响应，用于保存预览和保存详情。
- `RecordSavePage`：受控元数据表单、校验、快照槽位与保存 / 取消事件。
- `PlatformRecordStatus`：与执行状态分开呈现上传状态与重试事件。

预览的记录流程拆入 `workbench-records.js`，列表与双栏快照复用 `workbench-components.js`。正式 React 实现继续复用原有 primitives、tokens、Phosphor 和 i18n，不引入第二套设计系统。

独立验证：`node docs/redesign/verify-workbench-records.mjs`。覆盖快照与草稿隔离、失败响应保存、非法 JSON、必填名称、同 URL 连接隔离、跨项目详情、来源恢复、权限、脱敏、上传重试不调用 Tool，以及中英文 / 亮暗 / 四种宽度。正式服务版另需平台持久化、断线恢复、上传失败、重复事件、越权与并发 revision 测试。
