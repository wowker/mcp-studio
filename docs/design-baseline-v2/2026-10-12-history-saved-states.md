## 两种记录及恢复契约

调用历史是一次执行的快照。已保存记录拥有独立 ID、名称、备注、范围和上传状态，是可复用的请求或请求响应快照。编辑名字、备注与可见范围不改变请求和响应；删除已保存记录不删除原调用；原历史清理后保存快照仍然可读。

保存来源在打开编辑页时冻结，默认仅本人可见。保存表单校验空名称；模拟上传失败仍保留本次页面会话中的记录。维护者可管理项目记录，开发者可管理自己的私有记录，查看者只读；他人的私有记录不进入列表或详情。清理历史只针对当前筛选下已上传且未固定的记录，保留待上传及上传失败项。

恢复使用当前服务配置、环境及授权，而不是旧凭据。含 `[REDACTED]` 的顶层参数整体从新草稿移除，防止占位符被当作真实输入发送；提示具体参数名，必填项需补齐，可选项可保持跳过。保留普通参数的 0 / false / null 值，不覆盖已有草稿，不自动执行。

## 上传与脱敏契约

执行结果与上传状态独立：调用成功也可能上传失败。重试仅重传同一个记录快照，不新增调用、不重新执行工具、不生成新的保存记录 ID。上传任务按项目 + 连接 + 记录 ID 隔离，重复点击不创建并行任务；进行中禁止修改该保存记录。

原型共享一个脱敏预览模型，用于请求、响应、协议、复制、保存及上传快照。覆盖嵌套对象 / 数组、JSON 文本中的凭据字段、邮箱和手机号字段、Bearer / 认证头 / Cookie、敏感 URL 查询及 URL 内嵌凭据，也遮蔽已识别值在其他位置的回显。示例中的凭据与联系人均为虚构数据。

自定义规则每行一个 JSON Pointer，可指向参数、响应、协议、请求头或地址中的现有位置；不存在或超出范围的路径报错。规则仅作用于本记录、只能追加，自动规则不能关闭。已经上传的记录修改本地脱敏预览，不代表平台历史被重新写入。

此模型用于交互设计，不能保证识别任意业务敏感信息。正式开发需定义业务字段分类及敏感变量来源标签，在上传前与平台接收时复核，并实现权限、持久化队列、幂等上传、存储保留策略及历史修订流程。不要将原型的内存状态或正则规则直接视为生产安全边界。

## 评审路线

1. 打开脱敏示例：执行为成功、上传失败；重试仍失败，点击“模拟平台恢复”再重试，观察原记录成功上传。
2. 切换脱敏检查，输入 `/arguments/not_present` 查看错误；改为 `/arguments/customer` 并应用，快照隐藏整个对象。
3. 恢复到新调试页：保留原 Tab，新页未执行，提示补齐被移除的参数。
4. 在历史详情保存记录，清空名称触发校验；选择上传失败并保存，再从保存详情恢复平台并重试。
5. 返回列表组合筛选、查看详情再返回；翻到第二页查看已移除工具的记录。
6. 已保存列表查看“单个商品查询”的仅请求状态，以及“旧服务请求快照”的来源失效状态。
7. 切换英文 / 暗色主题，修改备注后切换语言，确认草稿保留。
