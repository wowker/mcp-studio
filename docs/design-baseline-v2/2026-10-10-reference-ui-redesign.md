# 根据现有 UI 截图的二次设计

日期：2026-10-10。此版作为设计演进记录保留；最新布局见[重新整理的调试工作台](./2026-10-10-organized-workbench.md)。调用仅为本地模拟。

## 1. 最新设计依据

用户提供当前产品截图，明确要求参考现有 UI 美化与二次设计。截图中的主要结构是：左侧功能导航、Tool Catalog、中央多 Tool Tab，以及上方输入 / 下方结果的纵向分栏。本轮采用这份截图作为布局基准，替代前几轮对“最初布局”的理解。

产品范围仍为 Server 配置、环境变量配置、Tools 调试、调用历史；用户、团队、项目与邀请作为基础能力。截图中出现的其他业务模块不因视觉参考而重新纳入范围。后端 Go、前端 TypeScript + React 和后端发起 Tool 调用的架构不变。

主预览：[workbench-preview.html](./workbench-preview.html)。

## 2. 保留并改进的结构

| 现有结构 | 二次设计 |
| --- | --- |
| 左侧常驻功能导航 | 保留；只显示四个业务入口，底部为团队成员和当前用户 |
| 顶部 Server / 项目入口 | 展示团队、项目和执行节点；下一行固定 Server、环境、凭据归属、连接状态 |
| Tool Catalog | 保留第二列，搜索名称 / 描述 / 参数；改进分组、选中态与省略规则 |
| 多 Tool Tab | 保留中央顶部；当前 Tab 使用细强调线，独立新增 / 关闭草稿 |
| Tool 局部功能切换 | 收敛为调试、Tool 定义、调用历史；移除不在本轮范围的保存项和脚本入口 |
| 上参数、下结果 | 保留纵向分栏；拖拽与上下方向键调整高度，可在页内扩大参数区域并恢复布局 |
| 结果状态及协议页签 | 状态、视图切换固定，内容区域独立滚动；原始 JSON 与调用详情按需阅读 |

美化重点是低饱和紫色强调、浅灰边界、白色工作面、统一控件尺寸、等宽协议标识、清晰的辅助文案。状态同时用文字 / 图标表达。普通区域不增加阴影或渐变，不堆叠装饰卡片。

## 3. Tools 参数区

简单参数在宽屏横向排列，让搜索词、数量和语言可以一起编辑；可选 Boolean 独立成行。Schema 放入页内折叠区。

复杂参数示例使用 `get_store_product_mapping` 的 `product_ids`：参数名、必填、类型、说明、可展开的详细帮助、数组编辑状态、宽幅 JSON 编辑框和字段错误分别呈现。示例为查询工具，所有调用均模拟，不连接截图中的真实 Server。

数组编辑器保留非法文本，不能通过点击已选中的 Form、切换 JSON 或运行动作静默丢弃。输入合法后同步规范化参数，运行前校验 1–20 个非空字符串。正式版本仍需实现数组逐项操作、对象、联合类型及完整 Schema 支持，本轮不声称已完成通用 Schema 编辑器。

“增加参数编辑空间”把当前页面输入区扩展到 65%，通过恢复布局回到默认 44%；不弹出独立编辑窗口。结果区仍保持可辨认的状态和入口。

## 4. 结果与历史

结果区固定状态行和“结果 / 原始 JSON / 调用详情”切换。结构化数组可显示为表格，其他演示内容保持 JSON；原始返回始终可查看。编辑下一次输入后，旧结果标明来自上次调用。

调用历史保留列表与概览页，点击记录进入完整详情页。请求、结果、Server、环境、调用人和协议详情都在页面内读取；浏览器前进 / 后退可用，返回保留筛选。恢复参数创建新的个人调试 Tab，不自动执行。

Tool 定义也在工作区内作为页面视图展示。弹框仅保留简短配置编辑、邀请和危险操作确认，不承载主要调试或历史阅读流程。

## 5. 响应式与身份边界

- 1024px 及以上保留完整三列；中间工作区仍为上下分栏。
- 760–1023px 缩窄功能导航为图标，保留工具目录和可调纵向分栏。
- 更窄窗口保留图标导航、将工具目录收敛为搜索与横向选择；参数与结果按顺序滚动，避免页面横向溢出。
- project / connection / tab / run 身份隔离、个人草稿、同 URL 独立认证及 Secret 约束继续有效。
- URL 只保存页面身份，不保存输入、Secret 或搜索词。示例状态保存在内存，刷新恢复初始数据。

## 6. 验证与交付边界

脚本：[verify-preview.mjs](./verify-preview.mjs)。覆盖三列布局、上下分栏、上下方向键调整、固定结果视图、数组校验与往返、模拟执行与快照、页面式定义 / 历史、恢复新 Tab、项目隔离、成员邀请及多种窗口尺寸。

截图与结果：[preview-assets/verification.json](./preview-assets/verification.json)。本轮只修改 `docs/redesign/` 的设计原型与文档，未修改生产 UI、数据库或 Go 服务。正式版本仍需完整授权、持久化、SSE、真实 MCP 兼容、正式共享国际化接入、深色主题与生产验证。

功能与服务架构继续参照[服务版设计](./2026-10-09-service-workbench-design.md)与[Tools 专项规划](./2026-10-10-tools-workspace-design.md)，布局建议以本文为准。


## 7. 双语与细节调整（2026-10-10）

用户要求界面标题只显示一种语言，项目支持中文与英文，语言入口位于左下角用户区域。默认简体中文；用户显式切换 English 后即时更新导航、标题、操作、辅助说明、状态、错误及可访问名称。工具定义页移除重复的英文 eyebrow，中文模块标题采用“服务配置 / 工具调试 / 环境变量 / 调用历史”。

使用已有 i18next，原型资源集中在 `preview-locales.js`，两种语言 key 集合相同；本地浏览器运行库及 MIT 许可保存在 `vendor/`，无新增 npm 依赖。正式 React 前端继续使用规范指定的共享 `src/shared/i18n` 与 `src/client/i18n`，原型状态代码不直接作为生产实现复用。

语言偏好只保存 `zh-CN` 或 `en-US`，无效值回退中文并清除；切换同步非敏感 Locale Cookie。页面不刷新、不改项目、连接、Tab 或 Run，不丢失非法参数草稿、未保存配置和滚动位置，不改变执行中的请求快照。计数由命名插值和 i18next 复数规则控制。服务提供的描述、返回内容、用户项目名称、JSON key、Tool 名称及参数值保持原文，界面语言不会改变请求里的 `locale` 参数。

视觉调整维持原三列和上下调试结构：导航背景减弱、工具列表文字更清楚、Tab 与工作区表面区分、主执行按钮增加可辨识度、输入与结果视图采用统一间距。工具定义使用两个平面分区，避免大面积空白卡片；窄窗口保留可操作的语言入口。调试、结果与历史仍使用页面。

新增验证脚本 `verify-preview-locales.mjs`，覆盖语言资源一致性、默认语言、偏好持久化与非法值、切换后的草稿 / 快照 / 焦点 / 滚动保留、未保存服务配置、执行中切换不重复调用、英语配置与调试流程，以及两种语言在 1440 / 1024 / 820 / 390px 下的核心操作可达性。原有交互回归继续由 `verify-preview.mjs` 覆盖。
