# Tools 调试重设计：三种方向与功能规划

日期：2026-10-10。状态：设计评审稿；可点击原型使用本地示例，尚未接入 Go 或真实 MCP Server。

最新布局选择：用户提供现有 UI 截图，采用左侧功能导航、Tool Catalog 和上下调试分栏，调试与历史使用页面。以[截图参考二次设计](./2026-10-10-reference-ui-redesign.md)为准。本文的三个布局保留作为参考，参数、执行、结果及隔离规划继续有效。

## 1. 本轮调整

上一版继续使用顶部四项导航、常驻 Tool 树、Tab 和参数 / 结果分栏，视觉和旧版过于接近。本轮改变工作区的信息层级与操作方式，提供三个结构不同的方案，避免把重设计缩减为换颜色。

业务范围仍为 Server 配置、环境变量、Tools 调试、调用历史。用户、团队、项目、成员邀请是平台入口，不新增测试平台、脚本、AI、报告或保存请求模块。后端仍为 Go，前端仍为 TypeScript + React。

比较原型：[tools-designs.html](./tools-designs.html)。通过 `?variant=A`、`B`、`C` 固定方案，底部比较条或左右方向键切换。编辑输入时方向键保持原编辑行为。

| 方案 | 空间组织 | 主要价值 | 取舍 |
| --- | --- | --- | --- |
| **A · 调试 Studio，推荐** | 左侧项目 / 业务导航；按需打开工具选择器；参数与结果占据主工作区；底部最近调用 | 连续修改参数、运行和排查结果的路径最短，结果空间充分 | 工具目录需展开；首次发现不如 B 直观 |
| **B · 工具目录** | 工具集合是主要入口；搜索、分类、能力说明在左；选中工具的参数与响应在右侧检查器 | 新用户能先理解工具作用、输入和风险提示，再执行 | 参数与结果纵向共用右侧区域，复杂输入调试更依赖滚动 |
| **C · 请求笔记本** | 收窄为图标导航；请求与响应纵向配对；独立右侧执行上下文和最近调用 | 阅读复杂 JSON、完整响应和上下文更自然 | 调整请求与查看长响应需要纵向移动；不适合大量快速切换工具 |

建议采用 **A 的调试主布局 + B 的工具选择器内容 + C 的执行上下文检查器**。仍是一个产品、一套 tokens 和 primitives，三种方案只用于选择设计方向；不作为三个长期维护的模式。

## 2. 视觉方向

- 从拥挤的 IDE 工具栏转为清晰的工作空间：项目导航、执行上下文、请求、响应各有固定位置。
- 浅色低饱和背景；白色工作面；强调色只出现在选择、焦点和运行操作。A 使用绿，B 使用蓝，C 使用暖棕，正式版选择一个全局方向。
- Tool 业务名称作为阅读标题；协议名称、参数路径、Run ID 用等宽字体。没有业务别名时直接展示 Server 名称，不通过 AI 编造名称。
- 参数、结果各自滚动；常见操作维持在固定区域。减少一层嵌套 Tab，把 HTTP / RPC / 环境 / 凭据信息归入“调用过程”并按需展开。
- 结果先显示适合内容类型的查看器，再提供原始数据。避免用户每次都面对一整屏 JSON。
- 沿用系统字体、Phosphor 图标和语义 tokens；不加入渐变、发光、大面积品牌色或营销式大卡片。目录项是能力列表，不是指标 Dashboard。

原型为中文、浅色设计评审面。正式实现需双语、完整深色 tokens、键盘分栏和响应式支持；不直接将演示代码复制进生产。

## 3. Tools 的主流程

```mermaid
flowchart LR
  A[选择项目与 Server] --> B[搜索并打开 Tool]
  B --> C[编辑个人参数草稿]
  C --> D[校验与固定执行快照]
  D --> E[Go 执行器调用 Tool]
  E --> F[内容预览与错误排查]
  F --> C
  F --> G[脱敏调用历史]
  G --> H[恢复为新草稿]
  H --> C
```

这条路径应在一个调试工作区完成。创建 Server、授权和缺失变量修复通过明确入口跳转或侧面板完成，再回到原草稿；不丢失用户输入。

## 4. 工具发现与打开

**选择器展示内容：**名称、描述、来源 Server、必填参数数量、只读 / 可能修改数据等 Server 声明。显示“Server 声明”，不能把 `readOnlyHint` 当权限或安全保证；未声明时显示未知，不猜测。

**搜索范围：**Tool 名称、描述、参数名。先按名称匹配，再按描述和参数匹配；显示命中片段。分类只使用真实元数据或项目显式配置，默认不靠名字自动编造分类。

**打开规则：**打开 / 切换 Tool 进入个人草稿；同一个 Tool 可有多份参数草稿。每份草稿绑定 project ID、connection ID、tool name、schema revision、tab ID 和 owner user ID。目录刷新更新能力列表，不覆写已编辑参数。

**定义变化：**已打开草稿保留旧输入，提示 Schema 已变化；显示新增、删除或类型变化，再由用户迁移并校验。执行端重新校验当前定义，不能把草稿的旧校验结果当成授权。

目录为空时分别呈现未连接、连接成功但无工具、权限不足和发现失败。无工具不等于连接失败。

## 5. 参数编辑：核心投入区域

**一份参数，两种编辑方式。** Form 和 JSON 编辑同一份规范化对象；非法 JSON 作为独立编辑文本保留，阻止运行及切换到 Form，不自动恢复旧值。切换不能静默丢弃未知字段或改变 `null`。

| Schema 能力 | 编辑方式与校验 |
| --- | --- |
| string / number / integer / boolean | 适当控件；枚举、范围、格式说明；输入错误定位到字段 |
| object | 折叠属性分组；必填标识；明确允许 / 禁止额外字段 |
| array | 添加、删除、排序项；显示元素类型与数量约束 |
| enum / const | 下拉或只读值；不以空字符串替代未填写 |
| oneOf / anyOf | 分支选择及匹配说明；保留合法值，切换前提示将丢弃的字段 |
| 缺省 / null / 值 | 三者明确区分；optional 字段可移除；仅 Schema 允许时可设置 null |
| default / examples | 可显式载入参考值；不暗中提交未编辑的默认值 |
| $ref / 递归 / 不支持的关键字 | 限制安全展开深度；提供定义与 JSON 编辑；明确校验能力边界，不伪造表单支持 |

错误展示在输入附近，并给出如 `items[2].quantity` 的路径；顶部只给错误摘要和跳转。前后端使用统一 API 契约，后端执行前完成权威验证。

JSON 编辑需有格式化、语法定位、只读 Schema 查看和键盘操作。大型编辑器按需加载，不为普通表单增加首屏负担。

**环境引用：**正式版只支持明确规定的引用语法及允许位置，不能随意在所有字符串上做模板替换。浏览器显示变量名称、作用域及是否存在，Secret 在后端解析。缺失变量和循环依赖定位到引用来源。环境 / Profile 切换遵循原有断开连接规则。

## 6. 执行与状态

运行前固定：调用人、项目、连接 ID、Tool / Schema 版本、参数、环境 revision、凭据绑定引用、超时。凭据原值及 Secret 环境值不写入浏览器草稿或 Run 默认响应。

**状态至少包括：**校验失败、等待授权、排队、执行中、取消请求中、完成、Tool 返回错误、传输失败、超时、中断 / 结果未知。按钮与结果状态由服务端 Run 和事件驱动，不能依据 Toast 或本地计时器判定成功。

运行中允许继续编辑下一次输入，但当前调用使用已固定快照。参数改变后明确显示“结果来自上次调用”；不能让结果标题看起来来自当前草稿。一次点击只创建一次 Run；同一草稿仍在执行时不创建重复调用。不同 Tab 的运行独立。

取消是发给 Go 执行器的请求，区分“请求已发送”和“停止已确认”。超时、网络断开或取消不证明远端没有产生副作用。UI 对结果未知的调用不自动重试。

SSE 事件按 run ID + sequence 更新，重连补事件。跨项目、切换 Tab、旧请求晚到，都不能把响应写到另一工作区。

浏览器仅调用 Inspector API；Go MCP 执行器向用户配置的 Server 发起 `tools/call`。部署节点无法访问用户电脑的 localhost；该场景通过后续本地 Agent 支持。

## 7. 响应与排查

默认三个视图：**内容、原始 JSON、调用过程**。结果区域始终可识别 Run、状态、耗时与来源快照。

| 响应类型 | 默认呈现 |
| --- | --- |
| structuredContent 对象 | 可折叠树、路径复制、节点搜索 |
| 同结构对象数组 | 可切换表格；支持复杂值进入节点详情，不能静默省略字段 |
| text | 纯文本；JSON 文本可显式切换解析视图；不直接执行 HTML |
| image | 受限图片预览、类型 / 尺寸；查看大图需明确动作 |
| audio | 类型、大小、按用户动作播放 |
| resource link / embedded resource | URI、内容类型、内容预览；不自动访问或执行外部资源 |
| 大结果 | 限量首屏呈现、大小提示、按需加载；保留截断说明，不把截断当完整返回 |

MCP `isError: true`、HTTP / 传输错误、参数错误、取消和超时分别呈现。工具业务错误可能在成功传输中返回，因此“HTTP 200”不能等于“Tool 成功”。有 `outputSchema` 时展示校验结果；不符合时保留实际响应并指出路径。

“调用过程”包括阶段时间线、请求快照、脱敏环境来源、认证归属、请求 / 响应协议事件与服务端关联 ID。Secret 不进入这些视图。没有记录的数据标为“未记录”，不从当前配置补出历史值。

## 8. 历史与复用

- 工作区底部或检查器显示本 Tool 最近调用；全量历史仍有独立一级入口。
- 历史按项目授权过滤，支持 Server、Tool、调用人、状态、时间筛选与分页；详情只读。
- 恢复历史建立新的个人草稿，标记来源 Run。绑定原 connection ID；原连接删除 / 无权访问时要求显式选择新连接并重新校验，不按 URL 自动匹配。
- 恢复后提示 Schema / 环境 / 凭据配置是否变化，不导入历史 Secret，不自动执行。
- 首版不加入独立响应比较、自动回放、脚本或测试创建；保持本轮功能边界。

## 9. 权限与协作

Viewer 可读获授权的配置描述与脱敏历史，不能执行或更改配置。Developer 可执行获授权的 Tool 并管理自己的草稿。Maintainer 可管理项目 Server、环境与项目成员；团队 Owner / Admin 的平台权限另行校验。

有项目访问权不自动获得每个凭据的使用权。个人 OAuth 属于 user + connection；项目服务凭据需明确授予使用权。运行权限由后端在每次调用检查，UI 禁用只是帮助解释。

默认共享 Server、环境配置和脱敏历史；个人草稿 / Tab / 个人 OAuth 不共享。涉及敏感业务输出时，可通过项目策略进一步限制历史阅读，不能依赖隐藏按钮。

团队成员、邀请和账号放在导航末端或项目入口，邀请继续支持指定初始项目角色、单次使用、过期、撤销及登录后接受。

## 10. 首版优先级

| 顺序 | 交付内容 | 验收重点 |
| --- | --- | --- |
| P0-1 | 项目 / 用户 / 连接身份，Server 与环境上下文 | 同 URL 不串凭据；项目和用户切换不串草稿 |
| P0-2 | Tool 发现、定义、基础及嵌套 Schema 参数编辑、JSON 模式 | 输入可无损往返；未知 / 不支持 Schema 可用 JSON 并明确限制 |
| P0-3 | Go 实际调用、超时、取消、SSE、状态与快照 | 状态权威；晚到响应不串 Tab；结果未知不自动重试 |
| P0-4 | 原始结果、基础内容查看器、错误分类、脱敏过程 | 业务错误和传输错误可区分；不执行返回内容 |
| P0-5 | 授权过滤后的历史、恢复新草稿、成员邀请 | 历史只读；恢复不调用；跨租户拒绝 |
| P1 | 高级 Schema 控件、表格 / 大结果优化、搜索与快捷键完善 | 不改变原始数据；完整键盘和大结果性能验证 |

复杂 Schema 在 P0 已可通过 JSON 编辑，不能声称所有自动表单已支持；P1 是提高可用性，不推迟后端完整校验。

## 11. 原型已覆盖与正式实现边界

原型覆盖：三个布局切换、工具搜索 / 分类、基础表单与 JSON 往返、非法输入阻止执行、模拟运行 / 取消 / Tool 错误、运行快照与继续编辑、结果表格 / JSON / 过程、只读历史详情、恢复未执行草稿、配置上下文与成员入口。

仅包含四个演示 Tool；所有只读声明、分类、环境版本、协议过程和业务名称都是示例。目录刷新、真实多 Tab、完整 Schema、多用户权限、SSE、认证和 Secret 存储尚未实现。本轮不修改现有产品代码、数据库或运行服务。

浏览器验证脚本：[verify-tools-designs.mjs](./verify-tools-designs.mjs)。截图和报告见 `tools-design-assets/`。正式开发仍遵守仓库前端规范，运行相应 focused tests 和 `npm run verify`。

## 12. 需要选择的设计方向

优先确认工作区结构，再定细节：A 的并排调试、B 的目录检查器，或 C 的纵向笔记本。可以采用 A 主工作区，搭配 B 工具选择和 C 右侧检查器；确认后细化正式组件、状态边界及 Go API 实施计划。
