# 05 · 权限与协作规则

[交付首页](./README.md) · [状态与数据](./04-states-and-data.md)

## 两层角色

团队角色管理组织关系，项目角色管理项目操作。一个人在不同项目可以有不同角色；团队管理员不因此取得他人的个人凭据。不能把顶部原型角色选择器当作正式鉴权实现。

| 团队能力 | 所有者 Owner | 管理员 Admin | 普通成员 Member |
| --- | --- | --- | --- |
| 创建团队项目 | 允许 | 允许 | 不允许；项目维护者也不例外 |
| 管理普通团队成员 | 允许，受保护规则约束 | 允许，受保护规则约束 | 不允许 |
| 调整其他管理员 / 授予 Admin 邀请 | 允许 | 不允许 | 不允许 |
| 移除所有者 / 本人 | 本轮不允许 | 不允许 | 不允许 |
| 修改所有者身份 / 转移所有权 | 本轮范围外 | 不允许 | 不允许 |
| 查看其他成员个人凭据 / 私有记录 | 不允许 | 不允许 | 不允许 |

Owner / Admin 可查看团队项目基本目录与成员管理信息，但项目配置、调用历史和调试须明确加入项目后访问。Admin 不能自行加入未授权项目；Owner 可通过页内确认为自己增加维护者身份，记录操作者、时间、项目、原因并公开到项目管理审计。接管不开放他人私有记录或个人凭据。

## 项目能力矩阵

以下要求用户已经具有该项目访问权。团队角色不得隐式绕过私人数据边界。

| 项目动作 | 维护者 Maintainer | 开发者 Developer | 查看者 Viewer |
| --- | --- | --- | --- |
| 查看共享服务配置、变量定义 | 允许，值已脱敏 | 允许，值已脱敏 | 允许，值已脱敏 |
| 修改共享服务配置 / 变量定义 | 允许 | 只读 | 只读 |
| 个人授权、连接、Agent、个人敏感值管理 | 本人范围允许 | 本人范围允许 | 不允许执行或修改 |
| 查看本人敏感值 | 有权且显式操作 | 有权且显式操作 | 原型禁止查看示例值 |
| 调试执行 / 取消 / 恢复为新调试草稿 | 允许 | 允许 | 不允许 |
| 查看项目调用历史与项目保存记录 | 允许 | 允许 | 只读 |
| 查看本人私有保存记录 | 允许 | 允许 | 有可见记录时只读 |
| 查看他人私有保存记录 | 不允许 | 不允许 | 不允许 |
| 创建 / 编辑 / 删除本人私有保存记录 | 允许 | 允许 | 不允许 |
| 发布 / 修改 / 删除项目保存记录 | 允许 | 不允许 | 不允许 |
| 固定 / 取消固定项目调用记录 | 允许 | 不允许 | 不允许 |
| 重试本人责任端持有的本人记录上传 | 允许 | 允许 | 不允许 |
| 重试他人本地待上传记录 | 不允许 | 不允许 | 不允许 |
| 保存合法 JSON、Schema 未通过的私有草稿 | 允许，不可发布 / 执行 | 允许，不可发布 / 执行 | 不允许 |
| 清理项目历史 | 允许，受清理条件限制 | 不允许 | 不允许 |
| 管理本项目成员角色 / 项目移除 | 允许，受保护规则约束 | 只读 | 只读 |
| 创建 / 撤销 / 重发本项目普通角色邀请 | 允许，受邀请授予上限约束 | 只读 | 只读 |
| 调整团队角色 / 团队移除 | 仅当另有团队管理权限 | 仅按另有团队权限判断 | 仅按另有团队权限判断 |
| 创建新的团队项目 | 仅当另有团队 Owner / Admin 权限 | 同左 | 同左 |

固定已确定为项目级保留标记，仅维护者操作。上传重试要求本人、有执行权限且责任端实际持有该记录；平台接收后的内部任务恢复由平台处理。原型已拆分固定、本人重试和项目访问判断；正式实现仍需平台端校验，不能将前端按钮作为权限边界。

清理只针对当前筛选中**已上传且未固定**的历史；待上传和失败项保留。已保存记录与原历史独立；编辑 / 删除上传中的记录不可用。他人私有记录不进入列表或详情，维护者也不能靠已知 ID 访问。

## 邀请规则

| 条件 | 设计要求 |
| --- | --- |
| 默认授予 | 团队成员 + 指定项目开发者，不隐含其他项目权限 |
| 邮箱比较 | 去首尾空白、转小写；正式邮箱验证由账号系统负责 |
| 同项目同邮箱已有 pending | 阻止重复创建，引导现有邀请 |
| 已是项目成员 | 不创建重复邀请，转成员角色管理 |
| 接受者身份 | 必须已登录、邮箱已验证且匹配；修复身份后仍要手动接受 |
| 接受授权 | 接受时重新验证邀请状态、期限和授权范围；完成时过期则不能加入 |
| 幂等 | 成功最多新增一个成员及一条项目关系；重复接受不重复授权 |
| 已有团队成员 | 保留其现有团队角色，邀请不降低 / 覆盖已有权限 |
| 已有项目关系 | 旧邀请不覆盖新关系；避免以旧角色回滚最近授权 |
| 重发 | 新 ID、新 7 天期限；旧及同邮箱 / 项目有效邀请置为 superseded |
| 授予 Admin | 仅团队 Owner；项目维护者不能重发授予 Admin 的邀请 |
| 已接受 / 撤销 / 过期 / 被替代 | 不可继续接受；已接受不显示重发 |

邀请 `entry` 是原型记录 ID，不是安全令牌。真实邀请的不可预测令牌、邮件投递、验证和一次性接受事务需正式实现；本交付不提供邮件服务或生产链接策略。

## 角色变更及移除保护

1. 项目至少一位维护者。降级或移除最后一位维护者必须先安排其他维护者。
2. 团队移除检查此人涉及的所有项目，不能绕过最后维护者保护。
3. 本轮本人及所有者受保护；团队 Admin 不能调整其他 Admin。角色下拉的“未加入”不能绕过移除确认。
4. **项目移除**只撤销该项目关系，保留团队与其他项目访问。
5. **团队移除**撤销团队和全部项目访问，并撤销该邮箱待接受邀请。
6. 历史与已共享记录保留操作者署名；不能将个人凭据转交给其他成员。
7. 页内确认必须列出目标和范围；取消不改变权限；处理中防重复；失败保留页面供重试。

正式实现须用服务端校验与事务保证并发下至少一位维护者。成员移除立即撤销平台项目访问并拒绝新操作；已发出的上游调用不保证撤销，不能清除对方设备已有数据。其项目内私有记录封存 30 天且不可访问，到期删除，期限内重加同一身份可恢复；个人凭据在线备份删除，不自动恢复，备份介质最多 30 天淘汰。Developer 降级 Viewer 后其私有记录只读，不能执行、编辑或重试上传。

## 权限在 UI 中的表达

- 可以查看但不能编辑：保留内容、显示只读说明，写入按钮禁用且能解释原因。
- 不具有对象访问权：进入权限页，不先展示内容再盖遮罩。
- 修改权限后：重新计算操作能力；不因旧页面仍开着就继续写入。普通成员失去项目关系后，也不能凭此前的维护者角色管理该项目成员。
- 切换项目后按目标项目关系计算能力；后台上传按记录所属项目校验。接管其他项目不改变当前项目角色。
- 无项目内容权限时隐藏服务上下文及流程进度；Owner / Admin 可以继续管理目录和成员，但这一例外不开放配置、历史、私人凭据或他人私有记录。
- 原型中的账号页 / 成员页角色预览保持同步且按项目隔离；正式产品使用权威能力响应，不提供自行切换角色的控件。
- 工具执行前、邀请提交 / 接受前、记录读取 / 上传前由权威端复核；前端能力用于呈现，不能作为授权凭据。
- 隐藏不适用入口与禁用可理解动作应保持一致，不能让用户点击后才得知基础角色限制。

权限矩阵、确认页及邀请摘要应使用同一能力定义生成，避免“说明可操作、按钮不可操作”或相反的漂移。

## 登录与敏感操作

内部版关闭公开注册，邮箱密码登录、邀请验证加入，SSO 后续接入。Owner 通过一次性初始化凭证创建；会话默认空闲 8 小时、最长 24 小时，可配置。凭据备份恢复需重新验证身份并仍有项目权限；平台托管密钥加密不等同端到端加密。平台离线时暂停新的项目调用，以确保工作台调用前可校验权限；持有上游凭据的用户通过其他客户端操作不受本平台保证控制。
