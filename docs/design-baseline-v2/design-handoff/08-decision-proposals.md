## MCP 调用方式 · 已确认

| 场景 | 谁实际调用 MCP | 平台后端职责 |
| --- | --- | --- |
| 远程 HTTP，浏览器可访问 | 浏览器前端直连 | 项目权限校验、配置、脱敏记录 |
| localhost HTTP，浏览器可访问 | 浏览器前端直连用户电脑服务 | 同上，localhost 不指平台服务器 |
| HTTP 浏览器受限或使用本机凭据库 | 用户明确切换后由本机 Agent 调用 | 同上，不静默接管调用 |
| stdio | 本机 Agent 启动进程并调用 | 不托管该本机进程 |

所有场景均由前端发起调试交互和编排；Agent 是用户电脑上的执行端，不是部署平台后端。平台默认不代发 MCP Tool 请求。调用历史的上传与可选个人凭据备份独立；D04 的调用前平台权限校验不等于平台代调用。

## D01 · 账号、登录与邀请身份

**已确认：内部版关闭公开注册，先采用邮箱密码 + 邀请加入；预留 OIDC 接入，SSO 不作为首版前置依赖。**

- 安装时以一次性初始化凭证创建首位 Owner，初始化完成关闭入口，不采用“第一个公开注册的人自动成为管理员”。
- 邀请默认 7 天，可选 1 / 7 / 30 天。新用户经邀请完成邮箱验证并设置密码；已有用户以匹配且已验证邮箱接受。
- 生产部署需配置邮件，承担验证、邀请和找回密码；可以复制邀请链接，但复制链接不代替邮箱归属验证。无邮件时不伪造已验证状态。
- 登录使用平台自己的会话，与每条 MCP 连接的 OAuth / Token 分离。默认空闲 8 小时、最长 24 小时，可由部署管理员配置。
- 平台会话以安全 Cookie 管理；退出撤销会话、断开工作台会话并清理当前用户浏览器缓存，MCP 上游令牌是否撤销另行操作。

理由：无需依赖企业身份供应商即可内部署，之后可以接 OIDC；代价是首版要提供邮件验证和密码找回。首版按邮箱密码交付；SSO 后续以独立设计变更接入。

## D02 · 管理员是否默认拥有全部项目数据

**已确认：团队管理权与项目内容访问权分开，必须明确加入项目才可读配置、历史或调试。**

- Owner / Admin 可查看团队内项目的基本目录信息和成员管理信息，不默认读取项目调用内容。
- Admin 不能自行给自己增加未加入项目的内容权限，由该项目维护者或 Owner 授予。
- Owner 保留显式项目接管入口：确认后为自己增加维护者关系，记录操作者、时间、项目及原因，并向项目管理记录公开。此前仍不能读取内容。
- 任何平台业务角色，包括 Owner，都不能读取他人的私有记录或个人凭据。

理由：方便组织管理，同时避免“管理员天然看到所有调试内容”。Owner 接管是明确、可追溯的例外，会新增一个小型页内确认流程；不改变个人数据边界。

## D03 · 固定、上传重试与角色变更

**已确认：固定是项目级保留标记，仅维护者操作；上传重试只处理本人设备 / 会话实际持有的本人记录。**

- 保留当前“固定记录不被清理”的语义，不把它混同个人收藏。Developer 不能固定 / 取消固定项目历史；Viewer 只读。
- 原始上传失败发生在生成记录的执行端。其他成员不能读取其私人本地队列，也不能代其重新发起 MCP 调用。
- Maintainer / Developer 可重试自己的记录上传；原 ID + 同一冻结快照幂等重传。平台已接收后的存储失败由平台内部任务恢复，不伪装成从其他人的设备重新上传。
- Developer 降级 Viewer 后，本项目私有记录可读但不可编辑 / 恢复执行 / 重试上传；恢复执行权限后才继续。成员移除后失去该项目全部平台访问，包括其项目内私有记录。
- 移除成员保留共享历史署名与已发布记录。未共享私有记录先按保留政策封存，管理角色不可读取或自动转为项目记录。

这是对原型通用 `canRun` 判断的已确认细化；当前按钮与动作已补充本人队列与固定权限判断。

## D04 · 本地记录、离线与刷新恢复

**已确认：记录由执行端可靠排队；浏览器持久化仅限已脱敏快照，原始参数、响应和凭据默认只在内存。首版不支持平台完全离线时发起新的项目调用。**

| 通道 | 队列责任 | 刷新 / 关闭后的行为 |
| --- | --- | --- |
| 浏览器直接 HTTP | 浏览器生成快照并上传，失败时脱敏快照放入按用户 / 项目隔离的 IndexedDB | 可恢复待上传记录；正在执行的网络调用不承诺恢复为可继续等待的任务，结果未知时如实标记 |
| Agent HTTP / stdio | Agent 生成快照并维护加密本地队列；浏览器展示状态 | 浏览器关闭后 Agent 可完成已获准的调用与排队；恢复页面后读取状态；上传仍需有效平台身份 |

- 一个 Run 只有一个队列责任端，不让浏览器和 Agent 各创建一份调用。平台以用户 / 项目 / 连接 / Run 身份及内容摘要检查幂等；同 ID 不同内容返回冲突。
- 平台不可达时，已发出的调用可结束并排队；新的项目调用等待平台权限校验恢复。这样避免把过期权限长期用于平台内的新调试。
- 提供“在此设备保留脱敏待上传记录”说明；公共电脑可选仅内存模式，明确刷新可能丢失待上传内容。
- IndexedDB 不是凭据库，也不是对同源脚本的安全隔离。浏览器存储可能被清理或受配额限制；不能承诺绝不丢失。失败队列不静默删除。
- 正常退出先提示未上传记录，可返回重试或明确丢弃后退出；会话到期时暂停上传并遮蔽内容，重新以同账号认证后继续。切换账号不开放前一用户缓存。

浏览器可持久化结构化数据是 IndexedDB 的能力，保留什么是本产品策略。[MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)

代价：无 Agent 的浏览器模式无法保证保留原始内容及跨刷新运行；需要长期本地保存凭据或更可靠后台队列的用户使用 Agent。

## D05 · 凭据长期保存与个人备份

**已确认：浏览器只保留会话凭据；长期本地保存使用 Agent 的系统凭据库。个人平台备份默认关闭，采用服务端托管密钥的加密备份。**

- 凭据归属为用户 + 项目 + 连接；敏感变量为用户 + 项目 + 变量定义。项目成员只能看到“已配置 / 缺失 / 过期”。
- 本机密钥存入系统凭据库；本地数据加密，主密钥与数据分离。不得将 Token 放进 localStorage、IndexedDB 或普通配置文件。
- 开启备份需明确对象和仅本人可恢复范围。备份在平台加密存储，密钥与数据库分开管理，恢复 / 删除记录审计。
- 本方案**不是端到端加密**。应用角色不能查看不等于具有基础设施最高权限的运营者在技术上无法解密；若需要后者，应改为用户持钥，但会增加恢复密钥与丢失后无法找回的流程。
- 新设备恢复需重新验证身份、仍有项目权限，再选择恢复到会话或 Agent；恢复过期 Token 不会让授权重新有效。
- 删除本机值、删除平台备份、撤销上游授权分成三个动作，明确各自影响。
- 成员移除立即禁止恢复，并删除在线系统中的该项目个人凭据备份；备份介质按不超过 30 天的周期淘汰。已有本机副本无法由平台保证擦除。

理由：先实现可运营的加密存储与恢复流程，不让用户首版承担密钥管理；需接受其不提供端到端保密保证的边界。

## D06 · Agent 安装、配对和信任

**已确认：Go 本机 Agent，先提供 macOS / Windows 安装包及 Linux 命令行；浏览器与本机通过受保护的回环接口通信。首版不引入浏览器扩展。**

- 首次配对展示准确工作台 Origin、平台用户、设备和请求能力；本机明确确认，配对码短期一次性使用。
- 接口仅绑定回环地址，校验 Host / Origin、已配对身份和短期会话令牌。不能把 CORS 白名单当作唯一认证。
- 设备通道可以复用，但每个项目 / 连接的 MCP 会话及凭据独立。平台登录凭证、Agent 通道凭证与 MCP 凭据不互用。
- 首次 stdio 启动核对命令、参数、工作目录和环境变量名；命令等执行配置变更后重新确认。命令以程序 + 参数数组执行，不隐式拼接 shell，不继承全部系统敏感环境。
- 解除配对后拒绝新请求并清理该配对会话；平台移除权限只约束工作台，不声称能阻止持有上游凭据的人使用其他客户端。
- 配对通道需要在 HTTPS 工作台、目标浏览器及本机网络策略下验证。若浏览器禁止回环通信，显示能力错误，不引导关闭浏览器安全机制。

MCP 传输规范明确建议本地服务仅监听 localhost、校验 Origin 并认证请求；本段配对体验与设备能力管理是基于这些约束已确认的产品规则。[MCP transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)

## D07 · HTTP、stdio、浏览器与 OAuth 支持范围

**已确认：以 Streamable HTTP 为主，兼容旧 HTTP+SSE；stdio 固定 Agent。浏览器首批验收 Chrome / Edge 最近两个稳定大版本。**

- 远程 / localhost HTTP 在能力允许时直连；CORS、混合内容、本地网络授权或 OAuth token endpoint 限制时提示具体原因，用户选择切换 Agent。
- 不静默更换执行端，不默认使用平台后端代理。配置页明确显示最终通道与凭据来源。
- MCP OAuth 采用授权码 + PKCE，并完成发现、目标资源绑定、回调校验及 scope 处理。浏览器不保存客户端秘密；需要受保护客户端秘密的场景交给 Agent 或明确提示不支持。
- 首版验收浏览器矩阵之外的 Firefox / Safari 提供能力检测，不承诺完全兼容；在完成验收后再扩展支持名单。
- 正式开发锁定已发布 MCP 版本与兼容矩阵，不跟随未发布 draft 自动改变行为。本稿引用 2025-11-25 说明约束，不宣称它是当前最新版本。

官方规范区分 stdio 和 Streamable HTTP，HTTP 授权规范不直接适用于 stdio；Chrome 还对本地网络访问引入独立权限，因此“地址是 localhost”不等于网页必定能连接。[MCP transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) · [MCP authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization) · [Chrome 本地网络访问](https://developer.chrome.com/blog/local-network-access) · [MDN CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)

## D08 · endpoint 查询参数

**已确认：允许非敏感查询参数，拒绝地址内嵌用户名密码、fragment 和认证秘密；敏感认证优先放 Header / 个人凭据配置。**

- 例如 `/mcp?workspace=demo` 可以保存，不能因存在 query 一概拒绝。
- 可使用非敏感变量引用；解析后属于敏感变量的值不得写入 endpoint query。
- 检测到 Token / API Key 等真实秘密时阻止保存共享 URL，并引导迁移到凭据或敏感 Header 引用。
- 本版不支持只能通过 URL query 传递认证秘密的服务；若实际服务必须这样做，再单独设计个人敏感 query 配置，不直接放宽共享 URL。
- URL 展示、日志、历史、复制共用脱敏规则；不能承诺仅凭参数名识别所有秘密。

代价：会限制少数使用 query secret 的服务，换取配置分享时清楚的边界。MCP OAuth 的 bearer token 不应被塞入 URL。[MCP authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)

## D09 · 高级 Schema 与“未完成草稿”

**已确认：校验语义完整、表单渐进支持；合法 JSON 但 Schema 不通过时，允许保存为仅本人可见的“未完成请求草稿”，禁止执行或发布到项目。**

- 普通对象、数组、枚举、nullable、嵌套字段提供结构控件；oneOf 在可明确区分时提供分支选择。
- anyOf / allOf 不简单转换成单选；能够无损表达时提供表单，否则该局部使用 JSON 编辑，并显示精确校验错误。
- 首批校验器覆盖声明支持的 Schema dialect；无声明时按选定 MCP 规范处理。支持文档内 `$ref`，首版不自动请求远程 `$ref`；不支持的 Schema 明确阻止执行，不能假装校验通过。
- 非法 JSON 原文只作为当前编辑器的未解析草稿保留，不保存为平台请求记录、不切回结构模式、不执行。
- 合法 JSON 的未完成草稿照常脱敏，显示“未完成 / 不可执行”；补齐后重新校验才可发布或执行。
- 已脱敏 / 截断字段不会自动恢复成可发送值；默认 skip、0 / false / null 等现有规则保持。

oneOf 是恰好一个分支有效，anyOf 是至少一个，allOf 是全部满足；这些语义决定不能用同一种分支控件处理所有组合。[JSON Schema 组合规则](https://json-schema.org/understanding-json-schema/reference/combining)

“未完成”标记已补入保存编辑、列表与详情；恢复后仍需重新校验。

## D13 · 脱敏、复制与历史修订

**已确认：默认所有持久化、复制、导出和上传都脱敏；采用“来源敏感标签 + 默认规则 + 项目规则 + 单记录追加规则”，平台接收端再检查。**

- 凭据和敏感变量带来源标签，派生字符串 / 嵌套值继承敏感性；认证头、Cookie、秘密 URL 和已识别回显属于不可关闭的保护。
- 项目维护者配置附加业务字段规则；执行者只能为自己的待上传快照追加脱敏，不能降低项目规则。默认遮罩已识别的邮箱 / 手机字段，规则应可预览解释。
- 原始响应可在生成它的本机会话中调试；平台历史只保留脱敏副本。首版不提供一键“复制全部未脱敏响应”。
- 已上传后发现遗漏：维护者发起追加脱敏修订，保留修改人、原因、时间等审计元数据，不在审计中保留被删除的秘密原文；更新关联保存快照及缓存。私有记录由其所有者在仍有写权限时处理。
- 无法可靠解析 / 脱敏的二进制或大内容默认只上传元数据和省略说明，不能静默上传原始内容。
- 自动脱敏无法识别一切业务秘密；提供上传预览和字段追加规则，不把默认正则当作完整数据分类。

## D14 · 命名、容量、保留和并发

**已确认以下初始默认值，之后按部署策略和权限调整：**

| 项目 | 已确认规则 |
| --- | --- |
| 项目名称 | 团队内去首尾空白、忽略大小写后唯一；不同团队可重名；改名不改 ID |
| 普通调用历史 | 默认保留 90 天，维护者可缩短；延长受部署上限约束 |
| 固定历史 | 不被普通清理任务删除，但计入项目容量；容量用尽不能静默解固定或删除 |
| 已保存记录 | 不随 90 天历史过期；直至有权用户删除，仍计入项目容量 |
| 项目初始记录容量 | 默认 5 GiB，可由部署管理员调整；接近上限提前提示，满时不静默丢记录 |
| 单次请求 / 响应留存 | 请求默认上限 1 MiB，超限在执行前提示；响应留存默认 10 MiB，超限明确标记截断 / 省略，不宣称完整快照 |
| 非文本 / 附件 | 首版提供受限预览或元数据；不能通过截断破坏格式后当作完整可下载附件 |
| 本地待上传队列 | 每账号 / 项目默认 1,000 条或 100 MiB，先到为准；7 天未上传提醒但不自动删除；满时提示处理队列再发起新调用 |
| 项目容量耗尽 | 阻止新平台内调用直到清理 / 扩容；已发出结果仍尝试排队。资源极限导致无法保留时明确展示记录丢失风险，不能写成“已记录” |
| 移除后的私有记录 | 封存 30 天且不可访问；到期删除；期间重加同一身份可恢复，个人凭据备份不自动恢复 |
| 平台数据备份 | 最多 30 天淘汰周期，删除后的备份残留不对普通用户开放 |
| 列表 | 默认 50 条 / 页，上限 100；按稳定游标分页；不一次渲染所有历史 |
| 并发编辑 | 版本号条件更新；冲突显示“配置已被他人修改”，保留本地草稿并允许比较，禁止静默后写覆盖 |
| 权限变更 | 下一次平台请求立即按新权限校验，Agent 不再发起新操作；已发出的上游调用不保证撤销 |

这些数值已由用户确认，属于首版产品默认和验收边界，不是性能实测结果。不得把业务容量限制混同压测能力保证。

## D15 · 技术契约与部署形态

**已确认：Go 模块化单体 + React / TypeScript / Vite + PostgreSQL；内部版使用容器组合部署。**

- 前端静态资源和平台 API 使用同一站点，由 HTTPS 入口统一提供；PostgreSQL 管理组织关系、配置版本与记录索引。
- Go 模块按身份 / 项目、配置、记录划分责任，首版不拆微服务，不把 Redis、消息中间件设为部署必需项。
- 平台 CRUD 使用 REST + OpenAPI；状态通知使用 SSE。Agent 通道独立使用经过配对认证的本机通信，MCP 自身按其 transport 执行，三者不混为一套协议。
- 跨语言采用共同的版本化接口定义与校验用例，而不是宣称 Go 和 TypeScript 可直接复用同一个运行时函数。
- 平台 MCP 执行凭据不成为共享服务账号；平台也不默认托管 stdio 进程。
- 记录索引与可查询结构可用 JSONB；要求字节保真的脱敏协议文本另存文本 / 文件，不能依赖 JSONB 保留空白、键顺序或数字原文。
- 租户以团队为隔离边界，所有项目访问明确携带团队和项目身份；服务端强制校验，数据库隔离策略作为额外保护。普通业务连接不使用数据库超级用户。
- Agent 本地队列使用轻量持久化与系统密钥保护；具体版本及 SDK 锁定在正式工程开始时通过兼容验证，不在设计讨论里承诺未经验证的版本号。

选择 PostgreSQL 是基于项目关系与可查询快照的需求；其 JSONB 有索引能力但不保留原始 JSON 表达。官方 Go SDK 可作为 MCP 实现起点，具体兼容性仍须验收。[PostgreSQL JSON 类型](https://www.postgresql.org/docs/current/datatype-json.html) · [行级安全](https://www.postgresql.org/docs/current/ddl-rowsecurity.html) · [MCP Go SDK](https://go.sdk.modelcontextprotocol.io/)
