## 使用规则与开发边界

- 先读 08，再按本页找到页面、交互和验收编号；详细合同以 01–06 为准。09–10 是原型变更与证据，不替代规则。
- 用户确认规则优先于领域文档及原型表现；旧后端集中执行方案、A/B/C 比较稿和早期工程计划只作历史参考。新增冲突须登记，不用原型偶然行为修改既定规则。
- 后续技术基线：Go 平台后端与本机 Agent，React / TypeScript / Vite 前端，PostgreSQL；优先内部容器部署，保留 SaaS 团队隔离边界。
- 浏览器负责调试编排，可访问 HTTP 由浏览器直连；受限 HTTP 或本机凭据库由用户显式切换 Agent；stdio 固定 Agent。平台负责身份、权限、配置、脱敏记录及可选个人备份，默认不代发 Tool 请求。
- 在另一个目录建立正式工程，当前包仅作设计参考。不得覆盖旧工程或 SQLite 数据；旧数据迁移不在本轮范围。
- 本次没有创建正式工程、接口、数据库或 Agent，也没有运行生产测试。新目录路径、协议字段、数据库和依赖版本等工程细化见 06。

## 标准组件与页面状态交付要求

组件规范见 [03](./03-components-and-visual-spec.md)。独立开发按基础控件、工作台、参数、执行结果、快照记录、服务授权、环境、项目成员、流程反馈的责任拆分；不直接移植原型字符串模板或内存模型。

每页至少登记适用的 `loading / empty / no-match / error / forbidden / missing / read-only`；对象不可读时不先渲染内容。每个会写入或执行的动作另有 `idle / validating / pending / success / failed / cancelled` 中适用的状态，不能以泛化“成功”替代连接、授权、保存、上传各自结果。不适用项应写明理由，不能通过强制制造无意义状态凑数。

| 区域 | 必查的异常与恢复动作 |
| --- | --- |
| 身份 / 项目 / 团队 | 验证失败 / 到期、账号不匹配、无成员关系、重复 / 过期邀请、最后维护者、提交失败保留输入 |
| 服务 / 授权 / Agent | 未保存、变量缺失、跨域 / 网络 / 协议失败、401、配对拒绝 / 过期 / 离线、凭据与备份分别失败、配置冲突 |
| 环境 / 参数 | 高层缺值、循环引用、无个人敏感值、类型错误、非法 JSON、Schema 不支持、可选项 skip、错误定位 |
| 执行 / 历史 / 已保存 | 无结果、运行中、取消 / 结果未知、业务 / RPC 错、上传失败 / 重试、记录不可访问、恢复缺字段、修订失败、容量满、截断 / 省略 |
| 全局 | 中英单语言标题、亮暗主题、宽窄 / 短窗口、长名称、键盘焦点、局部滚动、权限变化和迟到回调 |

## 最终验收登记方式

**A01–A60 全部是正式实现的待验收目标。** [06](./06-handoff-and-acceptance.md) 是用例正文，[CSV](./acceptance-register-v2.csv) 提供编号、场景、预期、状态、负责人、实现版本、证据与备注字段。开始开发后记录每项结果；通过必须有对应真实实现版本和证据，不将 209 项原型模型检查直接填入生产通过栏。

验收至少覆盖以下四层：

1. 组件：类型 / skip / 表单、禁用与加载、双语主题、长文本、键盘和焦点。
2. 领域：身份隔离、配置版本、环境解析、执行 / 上传状态、权限与记录生命周期。
3. 真实集成：浏览器 HTTP、Agent HTTP / stdio、OAuth、邮件、平台保存、持久队列及权限撤销；不用计时器模拟结果作为证据。
4. 连续旅程：登录 → 创建 → 邀请 → 服务 → 环境 → 调试 → 历史 → 保存 → 恢复，及 A60 的异常分支。运行新工程建立的等价类型、测试、构建和完整验证门槛；Go 后端与 Agent 单独补齐协议 / 进程测试。
