## 交接边界

Design baseline 2，确认日期 2026-10-12。用户已确认：“调用方式就按这个设计，其他规则按你的推荐方案，更新到设计交付文档里，暂时不进入开发。”D01–D15 不再是待确认的产品问题。当前已同步静态原型，生产工程未修改；最终页面 / 交互索引见 [11](./11-final-delivery-checklist.md)；同步过程与验证边界分别见 [09](./09-baseline-v2-prototype-sync.md)、[10](./10-baseline-v2-journey-review.md)。

前端发起调试；浏览器可访问的远程 / localhost HTTP 由浏览器直连，浏览器受限或需要本机凭据库时由用户切换本机 Agent，stdio 固定 Agent。平台后端负责用户、项目、权限、配置、脱敏历史与保存记录，以及显式开启的个人凭据备份，默认不代发 MCP Tool 请求。

## 原型同步状态

原先登记的登录初始化、项目接管、记录权限、队列与离线、容量、凭据恢复、Agent 确认、公开 query、未完成草稿、字号、脱敏修订及配置冲突，现已补充页面或明确的示例状态。入口与复核路径见 [09 原型同步](./09-baseline-v2-prototype-sync.md)。

本地存储、加密、邮件、会话安全、权限服务、Agent 进程与生命周期清理没有进入开发。原型只演示用户操作和状态反馈；真实刷新会重置业务状态，不能据此宣称 A01–A60 的生产验收已完成。D10 / D11 按用户确认的交付规则执行，不改写旧仓库规范。

## 剩余工程细化（不属于待确认产品规则）

- 锁定受支持的 Go / Node / React / SDK 与 MCP 版本，验证浏览器和服务兼容矩阵。
- 编写具体 OpenAPI 字段、事件消息、数据表、编号迁移与幂等 / 并发事务规格。
- 明确托管密钥轮换、配对握手、安装签名 / 升级、OAuth provider 适配细节并进行安全验证。
- 按 11 的最终页面和交互索引落成正式组件及真实状态；发现规则缺口登记差异，不能把原型模拟控件当作产品能力。
- 进行真实请求、鉴权、存储、容量、可访问性和性能验收；容量默认值不是性能实测保证。
- 旧 SQLite 数据是否迁入新平台不是本轮授权范围，另行确定迁移任务；不得覆盖旧工程或数据。

上述事项留给另一个目录的后续工作，本次不实施。

## 建议的后续工作顺序

这是一份交接顺序，不是本轮执行计划。

1. 在独立目录保留本设计包为只读参考，登记决策和版本；以已确认 D01–D15 为边界完成剩余工程规格。
2. 定义身份、能力、数据快照、执行 / 上传 / 授权状态及错误合同，前后端使用共同版本化合同与校验用例，保持跨语言语义一致。
3. 搭建主题、双语、Shell、基础组件与组件状态展示，再组合管理页和工具工作区。
4. 打通最小真实闭环：项目 → 一条 HTTP 服务 → 个人授权 / 环境 → Tool → 脱敏历史 → 保存 / 恢复。
5. 补齐 Agent / stdio、邀请权限、离线与备份，再按以下清单逐项验收。

旧仓库若涉及迁移，保留 SQLite 数据并增加编号迁移，不重写已发布迁移。新目录是否导入旧数据尚未形成实施范围，不能自动删除或替换旧工程。
