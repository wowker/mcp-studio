# 项目管理与团队邀请完整交互原型

日期：2026-10-12。仅更新 `docs/redesign` 的可交互原型与设计说明，没有进入正式开发。不连接账号系统、不发送邮件、不签发真实邀请、不持久化成员权限。业务状态只在当前页面会话中保存，刷新恢复示例数据。

入口：[项目管理](./workbench-preview.html?page=projects&project=commerce) · [项目成员](./workbench-preview.html?page=members&project=commerce&section=projectMembers) · [邀请记录](./workbench-preview.html?page=members&project=commerce&section=invitations) · [接受流程](./workbench-preview.html?page=invitation-detail&project=commerce&entry=team-invite-1&mode=accept)。

## 页面与交互

| 页面 | 交互与状态 |
| --- | --- |
| 项目管理 | 名称 / 描述搜索、当前项目标记、真实示例服务及成员数量、打开工作区、切换项目、管理项目成员 |
| 创建项目 | 页内表单、必填与重名校验、描述、保存中、失败保留与重试；成功创建空工作区与创建者的维护者身份 |
| 新项目起始页 | 独立空状态、配置首个服务、管理成员；不复制示例服务、凭据、变量或历史 |
| 成员与邀请 | 项目成员 / 团队成员 / 邀请记录 / 权限说明四个页面内入口；姓名邮箱搜索、角色或邀请状态筛选、空态 |
| 成员权限 | 团队角色、本项目角色、所属项目列表；保存进行中 / 失败 / 成功；保护本人、所有者和最后一位维护者 |
| 移除成员 | 分为项目移除与团队移除；页内说明对象和影响、确认 / 取消、进行中、失败保留与重试 |
| 创建邀请 | 示例邮箱、指定项目、团队角色、项目角色、1 / 7 / 30 天有效期；授予权限预览；格式 / 重复 / 已加入校验，创建失败重试 |
| 邀请详情 | 待接受 / 已接受 / 过期 / 撤销 / 被替代；创建及到期时间、角色、邀请 ID；重发 / 撤销页内确认 |
| 接受流程 | 邮箱匹配 / 不匹配、未验证、未登录；模拟登录验证；接受中、失败重试、成功及重复访问；接受时再次检查有效期 |

界面沿用灰白与低饱和绿色工作台：统一标题、紧凑表格、标准表单、右侧权限说明及底部操作。交互不使用模态对话框。移动窄屏将表单与说明上下排列，表格在局部区域滚动；两种语言沿用既有 i18next，主题使用现有 tokens 与 Phosphor 图标。

## 权限分层

- **团队所有者**：管理团队成员、管理员与项目；自己的所有者角色在本轮只读，所有权转移不在本轮范围。
- **团队管理员**：创建项目、管理普通团队成员；不能移除所有者、本人或修改其他管理员，也不能签发管理员邀请。
- **项目维护者**：管理所属项目的角色与邀请，不能创建团队项目、调整团队角色、移除团队成员或管理其他项目的邀请。不能重发授予团队管理员身份的邀请。
- **开发者**：调试、管理个人记录；成员与邀请管理只读。
- **查看者**：查看共享配置及记录；调试及管理操作禁用。

团队管理能力与项目使用权限分别表达；团队管理员不因此获得个人授权或凭据。页面内“权限预览”只模拟操作边界；它不更换真实账号，也不实现登录身份切换。既有顶部角色预览继续限制调试和配置操作。

项目至少保留一位维护者。移除任何项目最后一位维护者时必须先调整成员安排，不能通过团队移除绕过。角色选择不能通过“未加入”直接绕过移除确认。

## 项目切换与异步操作

项目 ID 是隔离边界。切换保留各项目在本次会话中的工具草稿、服务、环境、历史和保存记录，不复制凭据，不自动启动调用。新项目从空数据开始；创建表单按来源项目保存草稿，语言 / 主题切换保留输入。

创建、邀请、成员编辑及移除模拟进行中时禁止重复提交；离开相关流程或切换项目使未完成模拟操作失效，迟到回调不能污染新项目。正式开发需由服务端权限校验、幂等请求及数据层事务保证这些契约，原型没有对应后端。

## 邀请生命周期

1. 创建邀请不会直接添加成员；默认授予团队成员 + 项目开发者，范围为指定项目。
2. 邮箱按小写和去除首尾空白比较；相同邮箱在同一项目已有待接受邀请时阻止重复创建。已是项目成员时引导在成员页调整角色。
3. 接受必须使用受邀邮箱且已验证。错误账号、未登录或未验证均不能接受；模拟修复账号后仍须明确点击接受。
4. 接受失败保留邀请。成功最多新增一个成员和一条项目关系；已有团队成员保留原团队角色，已有项目关系不会被旧邀请覆盖。
5. 过期和撤销不可接受。即便开始接受时有效，在回调完成前过期也不能加入。
6. 重发生成新邀请 ID 和新的 7 天有效期；原邀请及相同邮箱 / 项目下其他有效邀请被标为已替代。旧邀请不能再接受；已接受邀请不提供重发。
7. 接受页是独立受邀者视角的**模拟预览**；顶部仍是设计工作台示例账号。查看成员列表可确认模拟加入结果，但不表示真实切换为受邀账号。

原型 URL 的 `entry` 只是示例记录 ID，不是访问令牌。刷新后，本次创建的临时邀请或项目不再存在。正式开发应另行设计不可预测令牌、邮箱验证、到期检查、撤销与服务端一次性接受事务。

## 移除语义

项目移除只撤销该项目的成员关系，保留团队身份及其他项目权限。团队移除撤销团队和全部项目访问，并撤销此邮箱的待接受邀请。两种操作都保留调用历史与已共享记录的署名，不把个人凭据转交其他成员。

原型通过成员表和权限变化演示影响。正式开发还需处理活跃会话、平台访问校验、个人凭据备份和数据保留策略；界面不会把“移除”宣称为清除对方设备中已经存在的数据。

## 评审路线

1. 项目管理 → 创建项目：尝试空名称、重名、模拟失败，再重试进入空项目。
2. 返回电商项目编辑工具参数 → 切到知识库 → 返回电商，检查草稿保留。
3. 成员页切换维护者 / 查看者权限预览，观察管理边界；查看权限说明。
4. 邀请成员：输入已有待接受的 `xiaoyu@example.com` 查看重复错误；使用新的示例邮箱创建邀请。
5. 接受流程切换账号不匹配 / 未验证 / 未登录；模拟修复后接受，先失败再重试成功，查看成员列表。
6. 查看 `casey@example.com` 的过期邀请，重发为新邀请；撤销新邀请并检查接受被禁用。
7. 成员详情更改项目角色，分别体验项目移除、团队移除，以及失败重试和取消确认。
