# Project workflow (M6 T33a)

`WorkflowProgress` owns ephemeral facts for the current identity lifetime. It stores only user, project, connection, Run, record and operation identifiers plus terminal execution status and explicit skip/view facts. It neither grants permission nor stores request/response/credential data. Refresh does not infer missing interaction evidence from configuration or list reads. A subsequently successful, owner-scoped platform detail GET may establish authoritative record evidence. `M2Memory.clear` clears it; project revocation removes only that project's facts. Suspension hides progress while retaining evidence for a same-account reauthentication.

`WorkflowPage` reads the existing permission-checked project configuration endpoints. A readable project proves the existing project step; the UI separately identifies creation observed in this session. Invitation completion is emitted after successful delivery, or the user explicitly skips inviting. Service progress uses a persisted connection. Environment progress follows `memory.applied` for that connection before its shared default; merely browsing an environment does not change progress. Existing applicable values must resolve; a missing effective environment remains incomplete. Zero-variable contexts require an explicit skip. Agent readiness uses the existing protected device preview and verifies returned project/connection/environment scope, binding its result to configuration version, variable versions and identity.

`runCompleted` is called only for a real terminal browser or Agent Run, retaining failed/cancelled executions without marking successful debugging. `historyViewed` marks a detail view for a known live Run. `historyObserved({userId, projectId, connectionId, runId, recordId, status})` may instead recover a Run after reload from a successful history detail GET, after root checks owner, record kind and snapshot identity. It stores no original upload operation ID: `WorkflowRun.operationId` remains undefined until a real live operation is observed. `savedObserved({userId, projectId, connectionId, runId, sourceRunId, recordId})` records a successful saved-detail GET only after the same owner, kind, snapshot and source checks. Its source Run must equal its snapshot Run; a saved observation alone never creates a history execution. Execution, upload, history view and saved upload remain separate: history requires the exact Run's recorded upload or its actual authority-confirmed platform history detail; saving requires a recorded browser saved operation or an actually read saved platform detail with the same source Run. A successful platform history detail also resolves the case where the server accepted the upload but the client lost its receipt; a failed local upload without that confirmation remains incomplete. `workflowUploads` projects identifiers and states from the existing browser operations and Agent Run states. Retrying an upload does not create a Run. Restoring a record creates an unexecuted Tab and emits no workflow execution fact.

Root integration owns actual successful-operation hooks, routing, shared translation registration and continuous production journey verification. Public page props are `client`, `project`, `session`, `memory`, `scopeRevision`, `connectionId`, optional `runId`, and `navigate`. Existing pages `members`, `servers`, `environment`, `tools`, `history` and `operations` are the continuation destinations. No backend API or authorization rule is added by this feature.
